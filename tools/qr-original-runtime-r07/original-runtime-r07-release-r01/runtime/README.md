# R07: un solo corte futuro del sandbox privado

Esta carpeta prepara fuentes para **un corte sintético posterior**. No despliega, construye Docker, crea credenciales, resetea el caso R12 ni modifica el runtime. R06, R04, corpus209, agentes y evidencias previas permanecen intactos.

Los setenta blobs API70 conservan exactamente la revisión `7f840536c16aea143c9d71264bd83866ee4731b7`. La imagen base futura debe ser exactamente `sha256:93dc84393cbaa83f680830c2e53bc7567e1c73a5273f46a36bb72df46fa9f740`, comprobada antes de construir con `--pull=false --network=none`. No se instalan dependencias ni se reemplaza el código API de esa base. Los archivos API de esta carpeta permiten comprobar procedencia; el Dockerfile sólo copia wrappers/helpers.

Se integra el notifier R06 byte exacto y sus cuatro permisos sintéticos. La creación/registro privado de su credencial y el refresco de las dos credenciales sintéticas existentes pertenecen al stager que ROOT revise; esta carpeta no los implementa ni lee ninguna credencial productiva. No se reutiliza la antigua especificación R06 de ID fijo: sólo se conserva el manifiesto/review histórico como procedencia.

`control_router.py` autentica primero `X-Evaluation-Control`. Sólo ofrece rutas y cuerpos fijos. La ruta existente POST `/control/start-original-case` acepta las tres claves originales I:SUP-01/I:SUP-02/M:SEC-05 y las doce claves nuevas M de seguridad/reclamo. Cada clave tiene un único hash de contrato; no se admite sender, SQL, URL, método ni credencial del caller. Los contratos de `originals/` y `security/` conservan las entradas y oráculos originales. Sus manifiestos locales actualizan únicamente referencias de dependencia y los catorce candidatos R12, sin atribuir aceptación ni ejecutar drivers históricos.

El sandbox mantiene HTTPServer serial. Usa **un solo control_lock** para start-case, original-case, snapshots, notificaciones, captura visual y despacho ASGI normal. Los hooks de seguridad y visual adquieren ese mismo lock internamente; el router no lo adquiere otra vez. Las tres fixtures anteriores se llaman dentro del lock, conservando sus cuerpos originales. El mismo engine de memoria y los tokens existentes se reutilizan entre casos; sólo se resetea su SQL sintético mediante el seed existente.

El harness conserva y relee el resultado, snapshot y diario terminado del caso anterior **antes** de enviar el siguiente inicio autenticado. El backend no recibe un callback de archivo, clave n8n, diario remoto ni archivo de aprobación. El presupuesto n8n, cupones, UNKNOWN y journals se conservan fuera del SQLite de fixtures. ROOT debe archivar el R12 real y su recuperación/cierre antes del único corte futuro; ninguna preparación de esta carpeta hace ese trabajo por inferencia.

POST `/control/visual-snapshot` tiene cuerpo exacto `{case_id, sender}` y sólo exporta el caso sintético vigente, incluido en la lista fija de doce SMOKE y quince contratos originales, scope2/2 y un pedido propio. No permite exportar otro caso registrado si no es el actual. El helper copiado de la propuesta visual toma la misma conexión SQLite bajo el lock y devuelve una imagen completa, fiel y acotada de los dos tenants sintéticos, con SHA y conteos. No reconstruye tablas a partir de JSON. El visor permanece local y se limita a 2/2. La imagen contiene datos técnicos del ensayo y debe guardarse de forma privada; no debe imprimirse ni publicarse su base64.

El proxy conserva origen fijo, autenticación del backend y sus límites previos; sólo añade las dos rutas de control. El controlador n8n conserva IDs, nodos, credenciales, conexiones y settings: únicamente añade dos ramas fijas a su validación de operaciones. Continúa siendo una propuesta OFF; no importa clientes de despliegue. El stager futuro debe comprobar metadata/readbacks actuales y registrar el cuerpo revisado, sin activar el agente ni alterar el ledger por esta preparación.

Los tres wrappers tienen inversión textual exacta a R06 salvo los cambios documentados en `provenance/source-transforms.json`. Las fuentes propuestas son revisables; los resultados locales que se produzcan no equivalen a ejecutar ni aceptar los quince originales. Sus respuestas reales seguirán requiriendo revisión literal donde corresponda.
